小说评审团 
一个人写小说，二十个人挑毛病。
一个 AI Agent 技能（Agent Skill）。把稿子丢进去，当场组一支虚拟评审团进场——二十个不同专业背景的评审坐在一张桌子前，对着你的文本逐条开火，互相质疑，最后由质量总监汇总出一份可执行的修改清单。
不是"AI 读后感想"，是结构化、分级、带原文定位的严苛审读。
技能遵循通用的 Agent Skills 规范，只靠一份 SKILL.md 加参考文件工作，不依赖任何平台专有接口。Claude Code、Codex CLI、Cursor、Windsurf、Gemini CLI、GitHub Copilot、WorkBuddy 等支持该规范的 Agent 都能直接用。
为什么做这个
写完一章，最怕的不是被骂，是没人骂。
朋友说"挺好的"，编辑要等排期，读者要等发布。等到真有人指出问题时，往往已经不是改一个字的事了。
这个技能填的就是这段空档：在你写完的那一刻，立刻有人进场挑毛病。
它和普通点评的区别
大部分小说点评读完只会留下一堆形容词——情节紧凑、人物鲜明、文笔流畅。这些话听了跟没听一样。
这里的每一条意见必须同时满足四个条件：
指出具体问题。 不是"节奏有点慢"，而是"第 12 章那场对峙用了三页写心理活动，把冲突的张力泄掉了"。
标注问题等级。 致命 / 严重 / 一般 / 轻微，四档必选一档，不许含糊。
落到具体位置。 哪一章、哪一段、原文哪句话，必须指出来。
给出可执行建议。 不是"建议再优化一下"，而是"删掉中间那段回忆，直接进对话"。
评审角色禁止说"写得不错""整体还可以""有潜力""氛围感很好""建议再优化一下"。允许肯定，但必须说清好在哪里，同时指出仍然存在的问题。只夸不挑等于没说。
评审团阵容
角色池二十人，各盯一段，职责不重叠。
叙事架构师 开场定调，先判断核心梗到底成不成立。这关过不了，后面所有人围着核心梗拆解，不去修表面文字。
主笔作者 查跑题、注水、重复、空转——删掉某一章是否影响故事。
场景调度师 管场景密度、镜头切换、画面感，处理该详写的略过、该略写的拖沓。
市场分析师 判断题材热度、卖点是否在前三章立住、目标读者能不能指名道姓。
逻辑审计员 管时间线和因果链。主角是怎么知道那件事的？有没有靠巧合硬推剧情？他知道的信息和他该知道的对得上吗？
设定考据员 核世界观、历史、职业、地理、常识，包括世界观规则有没有被自己打破。
生活控评审 审查对话与行为是否符合现实——金钱、时间、体力消耗、日常习惯是否穿帮。
心理学家 管人物动机。一个人崩溃、撒谎、背叛之前，稿子里有没有埋过钩子？他是不是在"因为剧情需要"而行动？
AI 检测员 专抓模板化表达。排比句是不是用滥了，每章结尾是不是都要升华一句，所有角色是不是都在用同一种语调说话。
体验风险评估师 找拖沓、崩人设、毒点、烂尾征兆。
细节统筹师 管穿帮。人名前后叫错没有，打火机上一章丢了这章又拿在手里，年龄和故事时间线对不对得上。
版权顾问 排查融梗、侵权、未授权引用风险。
质量总监 收口，整合意见，裁决争议。
文笔润色师 统一文风，删冗余，提语言质感。
节奏把控师 控制段落长短、叙事速度、留白。
对话优化师 让台词自然、有性格、去书面化。
伏笔统筹师 查埋了没收的坑，也查没埋就回收的"神来之笔"。
上下文记忆体 维护跨章节记忆，防前后矛盾。
读者评审员 从老白、小白、考据党、CP 党等视角预读，预判哪一章会弃书。
标题党 优化章节标题、封面文案、开篇钩子。
每名角色的详细攻击重点见 references/roles.md。
它会吵起来
最有用的一幕，是评审之间互相质疑。
逻辑审计员会说心理学家的判断偏轻，这地方不是情绪问题而是因果链断了。心理学家会接受因果链的判定，但坚持主角的崩溃仍然缺铺垫。
这种争执不是表演。两个专业视角撞在一起，往往才逼出真正的答案：一个问题是症状还是根因，优先级该往哪放。
争议最后由质量总监裁决。涉及核心梗、人物动机、时间线、版权风险的，不许和稀泥，必须给明确结论和理由。
两种模式
标准模式（默认）从二十人里挑最相关的八到十二人上场。四位固定在座——叙事架构师、逻辑审计员、体验风险评估师、质量总监，其余按题材加权。
写犯罪悬疑，多叫心理学家和设定考据员；写男频爽文，多叫节奏把控师和市场分析师；写言情，多叫对话优化师和读者评审员。稿子是什么样，评审团就配成什么样。
完整模式需要你明确说"全面评审""全员评审"。二十人全部上场，每人只攻自己最狠的一点，保证火力集中而不是无限拉长。
安装
技能遵循通用的 Agent Skills 规范，安装方式就是把它放进你所用 Agent 的技能目录。目录名必须写成 novel-review-panel，和技能本身的名字保持一致（技能名在 SKILL.md 里已经写定，目录名不匹配会加载失败）。
克隆仓库：
git clone https://github.com/chk8255975/novel-review-squad.git novel-review-panel
然后把 novel-review-panel 整个目录复制到你所用 Agent 的技能位置。
通用位置（多数 Agent 都认这一套）：
个人级技能目录：
~/.agents/skills/novel-review-panel/
项目级技能目录（只对当前仓库生效）：
<项目根目录>/.agents/skills/novel-review-panel/
各 Agent 的专属位置：
Claude Code 个人级 ~/.claude/skills/novel-review-panel/，项目级 .claude/skills/novel-review-panel/。
Codex CLI 个人级 ~/.codex/skills/novel-review-panel/，项目级 .codex/skills/novel-review-panel/。Codex 还需要在 AGENTS.md 里声明技能目录，否则不会主动扫描，加一行即可：
可用技能位于 ~/.codex/skills/，请根据用户请求匹配技能描述并加载。
WorkBuddy 个人级 ~/.workbuddy/skills/novel-review-panel/。
Cursor、Windsurf、Gemini CLI、GitHub Copilot 等支持 Agent Skills 规范的工具，找到各自技能目录放进去即可，格式完全一致。
Windows 用户把 ~ 换成用户主目录路径，.agents、.claude 这类目录可能默认隐藏，需要先在文件管理器里开启显示隐藏文件。
装好后重启 Agent 会话，技能自动生效。
怎么用
在对话里直接说，然后贴上文本：
- 帮我评一下我这章
- 让评审团看看这个大纲
- 开个评审会，挑挑刺
- 我这稿子有没有硬伤
- 全面评审一下（启用完整模式）
只贴文本不说别的，默认走标准模式，重点拆解核心梗、人物设定和剧情逻辑。
说"直接改"，它会先完成整轮评审，再输出修改稿，并标明改了什么、为什么改，不让你自己去比对。
输出长什么样
纯文字段落，分四段。
群聊启动 说明本次评审对象、评审模式、参与角色及各自关注点。
群聊记录 按发言顺序输出，每条为角色名、问题等级、发言内容。
质量总监汇总 整合成必须改、建议改、可保留、待观察四类清单，排出返工优先级。
终审结论 是否通过、是否需要返工、返工优先级、下一轮评审重点。
默认不使用表格，除非你明确要求。
一些边界
版权部分只做风险排查和提示。涉及具体法律判断时，它会建议你咨询专业律师，不代替律师下结论。
遇到不确定的专业领域——具体法条、历史细节、医学结论、技术参数——它会标注"此处需专业核实"，不硬撑。
稿子太长时会先说明这次覆盖到哪里、哪里没顾上，不假装全看完了。
它不替你决定创作方向。所有意见都是选项加依据，写不写、改不改、往哪改，决定权在你手里。
适合谁
自己闷头写、缺少第一读者的人。
连载中需要快速自检的人。
想把稿子投出去、在投之前先过一遍严苛审读的人。
替别人看稿、需要一套系统化检查清单的人。
