# 小说评审团群聊系统 (Novel Review Panel)

一个 WorkBuddy Skill：把小说稿子丢进去，自动组建一支虚拟评审团，让 20 个不同职责的评审角色在"群里"互相质疑、逐条挑刺，最后由质量总监汇总出一份可执行的修改清单。

不是泛泛的"读后感想"，而是结构化、分级、带原文定位的严苛评审。

## 它能做什么

你把大纲、章节目录、某个片段或者整稿交给它，它会：

1. 判断这是大纲、章节、片段还是整稿，以及属于哪个题材
2. 按题材挑选最相关的 8—12 名评审角色（也可以要求全员 20 人上场）
3. 由叙事架构师开场定调，先判断核心梗站不站得住
4. 各角色依次发言，每人必须给出问题等级、具体依据、可执行修改建议
5. 角色之间可以互相质疑，但质疑必须带依据
6. 争议交给质量总监裁决，涉及核心梗、人物动机、时间线、版权风险时不许和稀泥
7. 最后汇总成必须改 / 建议改 / 可保留 / 待观察四类清单，加上返工优先级和下一轮评审重点

## 评审团阵容

角色池共 20 名，覆盖创作的各个切面：

叙事架构师、主笔作者、场景调度师、市场分析师、逻辑审计员、设定考据员、生活控评审、心理学家、AI检测员、体验风险评估师、细节统筹师、版权顾问、质量总监、文笔润色师、节奏把控师、对话优化师、伏笔统筹师、上下文记忆体、读者评审员、标题党

每名角色的详细职责和攻击重点写在 `references/roles.md`。

## 两种评审模式

标准模式是默认的。它从角色池里挑 8—12 人，其中叙事架构师、逻辑审计员、体验风险评估师、质量总监固定在场，其余按题材加权。写犯罪悬疑就多叫心理学家和考据员，写男频爽文就多叫节奏把控师和市场分析师。

完整模式需要你明确说"全面评审""全员评审"。20 名角色全部上场，此时每人只攻自己最狠的一点，避免输出失控。

## 安装

把仓库克隆到 WorkBuddy 的用户级技能目录即可。仓库根就是技能本体，克隆后不需要再进子目录：

```bash
git clone https://github.com/chk8255975/novel-review-panel.git ~/.workbuddy/skills/novel-review-panel
```

Windows 用户把 `~/.workbuddy/skills/` 换成用户主目录下的 `.workbuddy/skills/` 即可。

装好后重启 WorkBuddy，技能自动生效。

## 怎么用

直接在对话里说，然后贴上你的文本：

- 帮我评一下我这章
- 让评审团看看这个大纲
- 开个评审会，挑挑刺
- 我这稿子有没有硬伤
- 全面评审一下（这会启用完整模式）

如果只贴文本不说别的，默认走标准模式，重点拆解核心梗、人物设定和剧情逻辑。

如果你说"直接改"，它会先完成整轮评审，再输出修改稿，并标明改了什么、为什么改。

## 输出长什么样

纯文字，分四段：

群聊启动（本次评审对象、模式、参与角色）、群聊记录（按发言顺序，每条带问题等级和修改建议）、质量总监汇总（四类清单加优先级）、终审结论（是否通过、是否返工、下轮重点）。

默认不使用表格。只有你明确要求表格时才用。

## 设计上的一些取舍

严厉是有边界的。这个技能禁止输出"写得不错""整体还可以""有潜力"这类空话，允许肯定但必须具体到好在哪里、同时指出仍存在的问题。

版权部分只做风险排查和提示。涉及具体法律判断时，它会建议你咨询专业律师，不代替律师下结论。

不确定的专业领域会标注"此处需专业核实"，不会硬撑。稿件过长时会先说明覆盖范围，不假装全看完了。
